# TaskPilot AI v0.2.0

TaskPilot AI v0.2.0 turns the v0.1 workflow demonstration into a more credible shared-service
foundation. It preserves the visible approval-first delivery flow while strengthening every boundary
around it: durable effects, independently scalable graph workers, federated identity, bounded
artifacts, isolated validation, and task-relevant repository context.

## Highlights

- Independent plan, repository-write, and validation-command approval gates persist across repair
  cycles and application restarts.
- Multi-file writes preflight and commit as one recoverable operation. Completed write and command
  effects replay by deterministic operation ID; uncertain commands fail closed instead of repeating.
- PostgreSQL-backed API and worker processes coordinate through skip-locked queue claims, renewable
  leases, expired-lease checkpoint recovery, and durable cross-process event refresh.
- OIDC validates signed access tokens against rotating JWKS keys with issuer, audience, time, and
  subject checks. Configured roles protect approval and administrator endpoints, and authorization
  decisions are auditable events.
- Local or S3-compatible immutable artifacts retain full patches and validation logs while checkpoints
  and public events stay bounded.
- Validation can run in a fresh network-disabled container with dropped capabilities and resource
  limits.
- Repository prompts receive deterministic relevance-ranked context rather than an alphabetical
  prefix of the tree.
- Declarative evaluation datasets run on isolated repository copies and assert outcomes, changed
  files, graph paths, and repair bounds through the public API.

## Compatibility and operations

- Python, web, and API metadata are `0.2.0`.
- SQLite and PostgreSQL schemas upgrade additively; existing v0.1 run metadata remains readable.
- Embedded mode remains the default. `api`, `worker`, and `all` execution modes opt into the durable
  queue boundary; `taskpilot-worker` runs the worker loop without an HTTP listener.
- Existing string-valued opaque token configuration remains valid; role-bearing token objects and
  OIDC are additive.
- Install the `auth`, `artifacts`, `postgres`, or `providers` extras for the corresponding optional
  production integrations. The release container installs the authentication support.

## Residual risks

TaskPilot is still a developer tool, not a hostile multi-tenant sandbox. Container command mode
isolates validation processes, but graph workers retain repository access. A crash that leaves an
external command uncertain requires operator review before retry. Production deployments must share
repository, operation, checkpoint, and artifact storage consistently and enforce TLS, identity roles,
object retention, and secret management outside the application.

The provider-backed multi-file live-model Scenario B passed as a release gate and was not substituted
with deterministic demo evidence. See the [v0.2.0 release-readiness record](../release-readiness-v0.2.0.md).
